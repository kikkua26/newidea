## 2. 功能模块详述

### 2.1 招标文件解析模块

**功能描述**: 自动解析招标文件，提取关键信息

**输入**: 
- 招标文件（PDF/Word/图片）

**输出**:
```typescript
interface TenderAnalysis {
  project_name: string;           // 项目名称
  project_overview: string;       // 项目概述
  technical_requirements: string[]; // 技术要求
  scoring_criteria: ScoringItem[]; // 评分标准
  qualification_requirements: string[]; // 资质要求
  bid_deadline: string;           // 投标截止时间
  key_points: string[];           // 关键要点
}
```

**处理流程**:
1. 文档格式识别和转换
2. 文本提取和清洗
3. AI分析提取结构化信息
4. 人工确认和修正

---

### 2.2 大纲生成模块

**功能描述**: 智能生成标书目录结构

**输入**:
- 项目概述
- 技术要求
- 评分标准

**输出**:
```typescript
interface Outline {
  id: string;
  title: string;
  description: string;
  level: number;        // 1-4级目录
  requirement_ids: string[]; // 对应的评分点
  children?: Outline[];
}
```

**生成策略**:
```
┌─────────────────────────────────────────────────────────────┐
│                   大纲生成策略                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   评分标准 ──→ 一级目录（与评分大类对齐）                    │
│                    ↓                                        │
│              二级目录（覆盖评分细项）                        │
│                    ↓                                        │
│              三级目录（具体章节）                            │
│                    ↓                                        │
│              四级目录（可选，细节展开）                       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.3 正文生成模块

**功能描述**: 多Agent协作生成高质量正文

**核心流程**:

```
┌─────────────────────────────────────────────────────────────┐
│                   正文生成流程                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Phase 1: 编排决策                                           │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ 对每个章节进行编排决策：                              │   │
│  │ - 是否需要表格                                       │   │
│  │ - 是否需要配图                                       │   │
│  │ - 引用哪些知识库                                     │   │
│  └─────────────────────────────────────────────────────┘   │
│                           ↓                                 │
│  Phase 2: 分组串行生成                                       │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ 同一一级目录下的章节串行生成：                        │   │
│  │ 1.1 → 1.2 → 1.3（串行，共享上下文）                  │   │
│  │                                                     │   │
│  │ 不同一级目录之间并发：                                │   │
│  │ [1.1, 1.2] ∥ [2.1, 2.2] ∥ [3.1, 3.2]（并发）       │   │
│  └─────────────────────────────────────────────────────┘   │
│                           ↓                                 │
│  Phase 3: 实时上下文更新                                     │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ 每完成一个章节：                                      │   │
│  │ - 生成章节摘要                                       │   │
│  │ - 提取新术语                                         │   │
│  │ - 记录交叉引用                                       │   │
│  │ - 广播给其他写手                                     │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.4 审核润色模块

**功能描述**: 多维度审核并润色生成内容

**审核维度**:

| 维度 | 检查项 | 权重 |
|------|--------|------|
| **内容完整性** | 评分点覆盖、内容充实度 | 30% |
| **逻辑一致性** | 章节间逻辑、论证完整性 | 25% |
| **风格统一性** | 术语一致、语气统一 | 20% |
| **格式规范性** | 标书格式、排版规范 | 15% |
| **语言质量** | 表达准确、无AI痕迹 | 10% |

**审核流程**:
```
生成内容 → 审核Agent → 审核报告
                ↓
        通过？ ─→ 是 → 润色Agent → 最终内容
                ↓
                否 → 返回写手Agent修正
```

### 2.5 共享上下文池

**功能描述**: 全局共享的上下文信息池

**数据结构**:
```typescript
interface SharedContext {
  // 术语表
  terminology: Map<string, {
    term: string;
    definition: string;
    aliases: string[];
    usage_count: number;
  }>;
  
  // 章节摘要
  chapter_summaries: Map<string, {
    chapter_id: string;
    summary: string;        // 200字以内
    key_points: string[];
    generated_at: Date;
  }>;
  
  // 风格指南
  style_guide: {
    tone: 'formal' | 'professional' | 'technical';
    perspective: 'first_person_plural' | 'third_person';
    formatting_rules: FormattingRule[];
    forbidden_words: string[];
  };
  
  // 交叉引用
  references: {
    from_chapter: string;
    to_chapter: string;
    context: string;
    type: 'see_also' | 'as_shown_in' | 'refer_to';
  }[];
  
  // 评分点覆盖
  requirement_coverage: Map<string, {
    requirement_id: string;
    covered_by: string[];  // 章节ID列表
    coverage_status: 'full' | 'partial' | 'none';
  }>;
}
```

### 2.6 知识库管理模块

**功能描述**: 管理历史标书、技术素材、企业资料

**知识类型**:

| 类型 | 描述 | 用途 |
|------|------|------|
| **历史标书** | 过往投标文件 | 参考复用 |
| **技术方案** | 技术解决方案 | 内容生成 |

### 2.7 导出模块

**功能描述**: 将生成内容导出为标准文档格式

**支持格式**:
- Word (.docx)
- PDF
- Markdown

**导出配置**:
```typescript
interface ExportConfig {
  format: 'word' | 'pdf' | 'markdown';
  template?: string;          // 模板文件
  include_cover: boolean;     // 包含封面
  include_toc: boolean;       // 包含目录
  page_settings: {
    page_size: 'A4' | 'A3';
    margins: Margins;
    header_footer: HeaderFooterConfig;
  };
}
```
