# 项目背景

## 1. 行业现状

### 1.1 投标市场痛点

投标文件编写是企业参与招标项目的核心环节，当前存在以下痛点：

| 痛点 | 描述 | 影响 |
|------|------|------|
| **耗时耗力** | 一份完整标书通常需要3-7天 | 人力成本高 |
| **质量不稳定** | 依赖个人经验，质量波动大 | 中标率低 |
| **格式规范复杂** | 不同招标方要求各异 | 废标风险 |
| **内容重复** | 相似项目重复编写 | 效率低下 |
| **协作困难** | 多人协作版本混乱 | 沟通成本高 |

### 1.2 现有AI编标方案的不足

目前市场上的AI编标工具存在以下问题：

```
┌─────────────────────────────────────────────────────────────┐
│                   现有方案的问题                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ❌ 独立生成 - 各章节互不关联，内容重复                       │
│  ❌ 缺乏上下文 - 不知道其他章节写了什么                       │
│  ❌ 风格不一致 - 术语、语气、格式不统一                       │
│  ❌ 无法引用 - 不能在正文中引用其他章节                       │
│  ❌ 质量无保证 - 没有审核和润色机制                           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 解决方案

### 2.1 核心思路

采用**多Agent协作架构**，模拟真实的标书编写团队：

```
┌─────────────────────────────────────────────────────────────┐
│                   Agent协作模式                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   📋 分析师 → 🌳 大纲师 → ✍️ 写手团队 → 🔍 审核员 → 🔧 润色师 │
│                                                             │
│   每个Agent专注自己的职责，通过共享上下文池协作               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 创新点

| 创新点 | 说明 | 解决的问题 |
|--------|------|-----------|
| **多Agent协作** | 不同角色Agent各司其职 | 专业化分工 |
| **共享上下文池** | 术语表、摘要、风格指南 | 一致性问题 |
| **流式上下文传递** | 实时广播章节完成信息 | 上下文缺失 |
| **分组串行+跨组并发** | 同组串行保证连贯 | 内容重复 |
| **多轮审核润色** | 审核→修正→润色 | 质量问题 |
